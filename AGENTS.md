# AGENTS.md: AI agent instructions for `cloudflare-preview`

This file is the context for AI coding agents (and a short guide for humans) working on this repo. It is the single source of truth. `CLAUDE.md` only points here. Nothing here assumes any tooling beyond Node, actionlint and shellcheck.

## Operating Rules

These are the rules agents miss most often, most-missed first. They override convenience. If a rule blocks you, satisfy it rather than work around it.

1. **Validate locally before every push.** Run `bash scripts/verify.sh`. It runs actionlint, shellcheck and `node --test`, the same gates as CI. Don't use CI as your first feedback loop.
2. **Never put a `${{ }}` expression inside a `run:` script.** Pass the value through `env:`. `test/static.test.mjs` enforces this for every action, workflow and example.
3. **No runtime npm dependencies, no bundling.** The scripts run as `node "$GITHUB_ACTION_PATH/…/src/x.mjs"` on the caller's runner, using only Node built-ins (`fetch`, `node:child_process`, …). Adding a dependency means shipping `node_modules/` or a `dist/`. Both are out of scope.
4. **Every public-surface change updates its docs in the same PR.** That means the `action.yml` input and output descriptions, then `node scripts/reference.mjs --write` to regenerate the README reference (a test fails when it is stale), and, when the behaviour changes, the README prose and an example. `CHANGELOG.md` is generated by release-please, so don't hand-edit it.
5. **PR titles are Conventional Commits** (`scripts/lint-pr-title.sh "<title>"`). The squash-merge subject drives the version bump.
6. **Never force-push or rebase a PR branch** that others may have reviewed. To absorb `main`, run `git merge origin/main`.
7. **Never make a real wrangler or Cloudflare call from tests or local experiments.** A logged-in wrangler on your machine will use your account. The tests use `test/helpers/fake-wrangler.mjs` and a fake GitHub API.

## Project Overview

These are composite GitHub Actions for Cloudflare Worker previews built in GitHub Actions. Each piece is its own action:

- `upload/` runs `wrangler versions upload` with retries and `--preview-alias`.
- `deploy/` runs `wrangler deploy` for production.
- `deployment/` records GitHub Deployments and their statuses.
- `preview-comment/` keeps the sticky preview comment.
- `comment/` is the generic sticky comment.

The root `action.yml` composes upload, deployment and preview-comment. `.github/workflows/preview.yml` is a thin reusable workflow made only from these actions.

The README opens with a caveat that stays there: **if Workers Builds can build the site, use Workers Builds instead.**

## Key Invariants

When you touch code, keep the invariant that guards it. Each one is covered by a test.

1. **Untrusted text never reaches a shell or a format string.** Commit subjects, author names and PR titles are untrusted. wrangler is spawned with an argv array (`src/lib/shellwords.mjs` splits author-supplied command strings without evaluating them). Placeholders are substituted in one pass, so a substituted value is never re-expanded. Markdown output goes through `inert()`.
2. **Redact before posting, and fail closed.** `src/lib/redact.mjs` runs on every comment body. A credential that can't be masked throws `SecretInCommentError`. The step then fails, and the body is never posted or printed.
3. **Structured output first, stdout second.** `WRANGLER_OUTPUT_FILE_PATH` ND-JSON is read first. The stdout parser is the fallback. Both are tested against real CI logs and real output files in `test/fixtures/`. Add a fixture rather than editing a real one.
4. **Comment state is trusted only from our own comment.** `findSticky` filters by author. `parseState` re-validates every field (40-hex sha, https URL, ISO time).
5. **A failed upload still updates the comment and the Deployment.** In the root action and in `deploy/`, the work step runs with `CFP_FAIL_ON_ERROR=false`. A final step fails the job.
6. **Bodies stay under GitHub's 65,536-character limit.** Redaction runs before measuring. Truncation closes any open code fence or `<details>`, and keeps the state tail intact.
7. **Every `CFP_*` variable an action sets is read by its script,** and every `inputs.x` is declared (`test/static.test.mjs`).
8. **The default wrangler command never downloads.** `src/lib/wrangler-command.mjs` picks the repo's own install from its lockfile. Any new package manager must have a local-only form, and a test in `unit.test.mjs` must cover it.

## Build & Test Commands

```bash
bash scripts/verify.sh   # actionlint + shellcheck + node --test (the local gate)
node --test test/*.test.mjs
node scripts/reference.mjs --write   # regenerate the README reference
actionlint .github/workflows/*.yml examples/*.yml
shellcheck scripts/*.sh
```

Requirements: Node ≥ 20, plus `actionlint` and `shellcheck` from your package manager (e.g. `brew install actionlint shellcheck` or `apt-get install shellcheck`, and actionlint from its releases). There is no `npm install` step, because there is nothing to install.

## File Structure

```text
action.yml               → root action: check secrets → deployment start → upload → deployment finish → comment → fail
upload/ deploy/ deployment/ comment/ preview-comment/   → one composite action each (action.yml only)
src/*.mjs                → one entry script per step (check-secrets, upload, deploy, deployment, comment, preview-comment)
src/lib/                 → actions (outputs/annotations), github (fetch client), wrangler (run + parse),
                           wrangler-command (lockfile detection), redact, sticky (marker comments),
                           preview-body (render + state), template, context, commit, shellwords
scripts/reference.mjs    → generates the README's input/output reference from the action.yml files
test/unit.test.mjs       → pure functions against fixtures
test/scripts.test.mjs    → entry scripts end-to-end: fake wrangler + fake GitHub API on a local port
test/static.test.mjs     → YAML guards (no expressions in run:, SHA pins, input/CFP wiring)
test/fixtures/           → real wrangler stdout and ND-JSON (provenance in unit.test.mjs header)
examples/                → copy-paste workflows (linted, and guarded like the real ones)
.github/workflows/       → ci.yml (lint, test matrix, smoke of the actions with a fake wrangler), pr-title.yml,
                           release.yml (release-please + moving major tag), preview.yml (the reusable workflow)
```

## Documentation Sync

| Change | Update |
| --- | --- |
| Add or change an action input or output | that `action.yml`, then `node scripts/reference.mjs --write`; the reusable workflow if it forwards it |
| Change a default | the same, plus `grep` the old value across README prose, examples and AGENTS.md |
| Change what a piece needs from GitHub | the `# Permissions:` header in its `action.yml` and the README permissions column |
| Change the comment layout | `DEFAULT_TEMPLATE`, the placeholder list in `preview-comment/action.yml`, and the README sample |

## Release Process

release-please opens a release PR from Conventional Commits. Merging it tags `vX.Y.Z`. `release.yml` then moves `vMAJOR` to the same commit. `preview.yml` pins this repo's own actions by version on lines marked `x-release-please-version`, so release-please bumps them. Details are in [RELEASING.md](RELEASING.md).
